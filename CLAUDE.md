# Правила проекта auto_dealer_bot (Pick+ Auto)

## Железные правила публикации
- ЛЮБОЙ новый канал/генератор контента (пост, видео, озвучка, статья,
  карусель, будущие) ОБЯЗАН проходить через `validate_post_before_publish()`
  (`post_validator.py`) ДО генерации — только через результат этой проверки
  (`ValidatedCar`, тоже из `post_validator.py`), не через сырой `car`-словарь.
  При добавлении фичи первым шагом показывай, где стоит гейт.
- Лимиты (проверяются внутри `validate_post_before_publish()`): пробег
  <= `config.MAX_MILEAGE_KM`, итоговая цена под ключ в
  `config.PRICE_MIN_RUB`-`config.PRICE_MAX_RUB` И (если для модели заполнено)
  в `model_specs.ModelSpec.price_range_rub`, год выпуска в диапазоне
  `config.MIN_YEAR`-`config.MAX_YEAR` (сейчас 2022-2023 — не "не старше
  N лет", а фиксированный узкий коридор, при необходимости уточняй текущие
  значения в `config.py`, а не полагайся на цифры из этого файла).
  Прецеденты брака: Chevrolet Trax за ~5 млн ₽ (модельный ценовой диапазон
  не был заполнен), видео с пробегом 100к+ (генератор вызвали в обход гейта),
  Kia K5 (encar #42247766) за 37.9М ₩ — выше даже цены нового ТОП-трима
  (Signature, 34.69М ₩) — исходная корейская цена объявления выше
  `model_specs.ModelSpec.new_price_max_krw` (см. `check_price_vs_new_krw()`,
  2026-07-21) — БЕЗ допуска на наценку (потолок и так самый дорогой трим),
  source-независимый рубеж поверх `check_price_sanity()` (та живая, но
  только для Encar и только когда площадка отдала originPrice именно для
  этой комплектации). ⚠️ `new_price_max_krw` заполнен только для 1 из 99
  записей `model_specs.SPECS` (только Kia K5) — для остальных моделей
  `check_price_vs_new_krw()` пишет WARNING в лог вместо тихого пропуска
  (см. её докстринг), но публикацию не блокирует — дозаполнять справочник
  нужно постепенно, как и `price_range_rub`.
- **Групповой ценовой гейт БЕЗ справочника** — `post_validator.
  check_price_vs_batch_median()`, вызывается в `target_collector.py`/
  `broad_collector.py` СРАЗУ после `filter_year_range()` (этап парсинга, а
  не `validate_post_before_publish()` — ему нужна вся партия лотов одной
  модели из текущего прогона, не один `car`). Группирует по (brand, model),
  внутри группы с >= `config.MIN_BATCH_N` (5) priced-лотов сравнивает с
  `config.BATCH_MEDIAN_FACTOR` (1.3) × медианой партии — REJECT в
  `rejected_posts.log`. Группы меньше `MIN_BATCH_N` не проверяются. Добавлен
  2026-07-21 как универсальное дополнение к `check_price_vs_new_krw()`
  (справочный, закрывает только 1/99 моделей) — этот работает для ЛЮБОЙ
  модели без ручного заполнения цены, но требует, чтобы в партии
  ТЕКУЩЕГО прогона реально было >= 5 лотов этой модели.
- Ошибка одного канала не должна ломать другие (try/except + лог) —
  см. `agent_publisher.publish_post()`: VK обёрнут в try/except вокруг
  вызова, чтобы сбой VK не мешал уже отправленному Telegram.

## Токены и секреты
- VK: пользовательский токен (получают через Kate Mobile), НЕ токен
  сообщества — групповой не умеет `photos.*`/`video.*`. Нужные права:
  `photos,wall,groups,video` (см. `SETUP_GITHUB_ACTIONS.md`).
- Секреты только в `.env` (есть в `.gitignore`) и GitHub Secrets. Никогда
  не выводить значения токенов в чат, логи и коммиты.
- При смене токена напоминать обновить секрет `VK_TOKEN` в GitHub
  (Settings → Secrets and variables → Actions).

## Скачивание фото
- Всегда браузерный User-Agent + Referer (`vk_publisher._referer_for()`):
  для `ci.encar.com`/`fem.encar.com` — `https://www.encar.com/`, для
  остальных источников — домен самой ссылки на фото. Валидация в
  `vk_publisher._download_photo()`: HTTP 200, `content-type` начинается с
  `image/`, размер > 10 КБ (`_MIN_PHOTO_BYTES`), до 3 попыток.
- Загрузка каждого фото в VK (`_upload_one_photo()`) тоже ретраится целиком
  (не только скачивание) до 3 раз. VK-пост публикуется, если успешно
  прикрепилось хотя бы `config.MIN_PHOTOS_FOR_POST` фото — не обязательно
  все заявленные (частичный набор не блокирует пост целиком). Это ОТДЕЛЬНАЯ
  настройка от `config.MIN_PHOTOS_PER_POST` (та — гейт ДО публикации, на
  основе исходного числа фото у объявления).

## Устройство проекта
- Списки моделей: `target_models.json` (активный поиск в
  `main_pipeline.py`, targeted-режим) + `model_specs.py` (см³/л.с./
  ценовой диапазон) — добавлять ТОЛЬКО через `add_model.py` (пишет
  одновременно в оба файла, иначе рассинхрон — так уже терялась модель,
  доступная только broad-режиму).
- `watchlist.py` — два независимых списка для `main.py` (формат
  "цена изменилась"/"новое поступление"): `WATCHLIST` — страницы новых
  авто у дилеров на carnoon.co.kr, `USED_CAR_SEARCHES` — сохранённые
  поиски б/у авто на kbchachacha.com. Это отдельный путь от
  `target_models.json`/`main_pipeline.py` (лидогенерирующие посты).
- Публикация текста: `post_text_builder.prepare_post_fields()` — ЕДИНАЯ
  функция подготовки полей поста (расчёт цены, заголовок, проверки на
  хангыль/пустое название), используется вообще всеми путями. Два тонких
  builder'а поверх неё, отличаются только шаблоном и парой полей:
  `lead_post_builder.build_lead_post()` (main_pipeline.py, CTA на
  `@korea_auto_kazan_bot`) и `price_alert_builder.build_price_alert_post()`
  (main.py, статус "новое поступление"/"цена изменилась"). Готовой функции
  `build_post_text()` в проекте нет — не путать с этими двумя.
- Тесты в бою: workflow `run_bot.yml`, галочка `test_post` (форс-публикация
  одного поста в оба канала, дедуп игнорируется) — текст получает префикс
  `[ТЕСТ] `. Галочка `test_video` (только вместе с `test_post`) —
  дополнительно временно включает `VIDEO_ENABLED`/`VOICE_ENABLED` на этот
  один прогон, не трогая плановые настройки.
- GitHub Actions — боевая сеть, отличается от локальной в обе стороны:
  encar-CDN (`ci.encar.com`) отдавал заглушки без браузерных заголовков
  именно оттуда; а видео-CDN VK (`ovu.mycdn.me`) наоборот упирался в
  `connect timeout` только с локальной машины разработчика, на GitHub
  Actions грузилось нормально. Не полагайся на то, что "работает локально"
  = "будет работать в проде", и наоборот.

## Контент-потоки — не смешивать
- Два НЕЗАВИСИМЫХ потока контента, разные данные, разный формат, разный канал:
  1. **TG/VK-лидоген** (`lead_post_builder.py`/`price_alert_builder.py`,
     `post_text_builder.py`, формат `post_format_schema.py`) — посты про
     ЧУЖИЕ объявления с корейских площадок (Encar/KBChachacha/Charancha/
     OnBid/Heydealer), CTA на бота `@korea_auto_kazan_bot`, публикация в
     `config.TELEGRAM_CHAT_ID` (публичный канал). Формат ЗАФИКСИРОВАН (хук
     🔥/📊, блок "📋 Характеристики", CTA `👉 ... @бот`) — не трогать.
     Единственное добавление сюда — хэштеги в конце (см. ниже).
  2. **Яндекс/Дзен-витрина** (`yandex_post_builder.py`/
     `yandex_post_validator.py`/`yandex_publisher.py`) — посты про СВОИ
     лоты дилера (реально куплено/заказано), CTA на телефон/сообщение в
     профиле (бота НЕ упоминаем — у Яндекс Карт нет своего бота), тексты
     уходят ЧЕЛОВЕКУ в служебный TG-чат (`config.YANDEX_DRAFTS_CHAT_ID`) на
     копирование в кабинет Яндекса — у Яндекс Карт нет API публикации (см.
     "Стиль работы" ниже про несуществующие API).
  Данные (car-словарь) общие (те же поля, что использует лидоген), но
  дальше пути НЕ пересекаются — не переиспользовать один builder в другом
  потоке и не путать их чек-листы валидации.

- **Хэштеги в TG/VK** (`post_text_builder._build_hashtags()`, поле
  `hashtags` в `prepare_post_fields()`, добавляется в конец обоих `.txt`
  шаблонов) — 3-5 штук: `#автоизкореи #подзаказ #казань #{марка+модель}`.
  `#подзаказ` — везде без исключений: весь лидоген про чужие объявления с
  площадок, которые можно заказать, а не про собственный склад — сверяться
  с `own_stock.json` здесь НЕ нужно (та логика — только для Яндекс-потока).
  В Яндекс-версии хэштеги (символ `#`) ЗАПРЕЩЕНЫ валидатором.

- **Статус лота (in_stock/under_order)** — только для Яндекс-потока
  (`yandex_post_builder.resolve_stock_status()`). По умолчанию ВСЕ лоты —
  `under_order` (дилер привозит машину из Кореи под заказ, это и есть
  услуга). `in_stock` — исключение, ставится вручную: вписать external_id
  (или url, если id нет) лота в `own_stock.json` — простой JSON-список,
  правится руками, без своего скрипта по образцу `add_model.py` (тут
  формат проще, отдельный генератор не оправдан).

- **Два шаблона Яндекс-поста** (`yandex_post_builder.py`,
  `UNDER_ORDER_*_TEMPLATE`/`IN_STOCK_*_TEMPLATE`) — формулировки утверждены
  построчно, менять текст можно только по прямому запросу:
  - `under_order`: заголовок `"{title} {year}, {mileage_km}, под заказ"`,
    первая строка текста `"{title} {year} — привезём под заказ..."`, в
    тексте состав цены ("в цену уже входят выкуп, доставка, растаможка и
    оформление ЭПТС"), срок поставки `{config.DELIVERY_DAYS_MIN}–
    {config.DELIVERY_DAYS_MAX}` дней (45–60 — реальный срок Корея ->
    Владивосток -> автовоз -> Казань), CTA "Записаться на консультацию".
  - `in_stock`: заголовок `"{title} {year}, {mileage_km}, в наличии"`,
    машина уже привезена/растаможена, CTA "Записаться на просмотр".

- **Полный чек-лист `yandex_post_validator.validate_yandex_post()`**
  (блокирует отправку, см. её докстринг для деталей регэкспов):
  1. Год выпуска обязателен и в заголовке, и в первой строке текста (как
     в примерах — "Kia K5 2021").
  2. Пробег — точное число в заголовке, без диапазона/"до".
  3. Цена — точное число с ₽, без диапазона/"от"-"до" (срок поставки —
     ЕДИНСТВЕННОЕ поле, где диапазон разрешён, не проверяется на это правило).
  4. CTA обязателен и должен соответствовать статусу (консультация/просмотр).
  5. `under_order`: слова "в наличии"/"привезён(а)"/"растаможен(а)"/
     "просмотр" запрещены (машина ещё в Корее, смотреть нечего, совершённый
     вид не подходит).
  6. Согласование рода: "привезена"/"растаможена" запрещены ВСЕГДА
     ("автомобиль" мужского рода) — независимо от статуса.
  7. "ПТС" без "Э" запрещено — с 2020 года новые ПТС только электронные.
  8. Минимум 2 из 3 ключевых фраз (`KEY_PHRASES`) должны присутствовать.
  9. Ни одна ключевая фраза не повторяется между абзацами.
  10. Символ `#` запрещён (хэштеги — только TG/VK).
  11. `hp` лота выше `customs_calculator.MAX_HP_FOR_PHYS_LGOTA` (160) — блок
      ТОЛЬКО если для этой же модели в `model_specs.py` есть известная
      версия В ПРЕДЕЛАХ льготы (см. `model_specs.model_has_privileged_hp_variant()`,
      пример — Kia K5: в SPECS есть 2.0 MPi/160 л.с., но у модели есть и
      более мощный 1.6T GT-line — высокий hp у лота может значить, что
      комплектацию перепутали, и коммерческий утильсбор посчитан там, где
      могла быть льгота). Если у модели вообще нет варианта в пределах
      льготы, или модель не отслеживается в `model_specs.py` — НЕ блокируем
      (нет данных для сравнения — не гадаем). `MAX_HP_FOR_PHYS_LGOTA` —
      тот же порог, что использует `customs_calculator.util_calc()` для
      расчёта льготы физлицу (единый источник числа 160, не дублировать).

- **`config.YANDEX_DRAFTS_CHAT_ID`** (по умолчанию = `ADMIN_CHAT_ID`) —
  единственный адресат Яндекс-черновиков. `yandex_publisher.send_yandex_draft()`
  поднимает `YandexDraftBlockedError` и НЕ отправляет ничего, если
  `YANDEX_DRAFTS_CHAT_ID == TELEGRAM_CHAT_ID` — защита от случайной утечки
  недосмотренного черновика в публичный канал лидогена. Тестовый прогон —
  `test_yandex_post.py` (пинг в служебный чат + один стаб-лот с префиксом
  `[ТЕСТ] `, статус по умолчанию under_order), НЕ входит в CI, только
  вручную.

- **Очередь Яндекс-черновиков** (`yandex_queue.py`, вызывается из
  `main_pipeline.py`) — лидоген публикует лоты в TG/VK чаще, чем нужно слать
  Яндекс-черновики:
  - После КАЖДОЙ успешной (не dry-run) публикации в TG/VK лот кладётся в
    `yandex_queue.json` (`yandex_queue.enqueue_lot()`) — сразу НЕ отправляется.
  - Отдельным шагом в конце прогона `main_pipeline._dispatch_yandex_draft()`:
    если с последней отправки прошло >= `config.YANDEX_MIN_INTERVAL_DAYS`
    (по умолчанию 2 дня, см. `yandex_queue.due_for_send()`) — забирает из
    очереди ОДИН лот (`yandex_queue.pick_best_lot()`) и шлёт черновик.
    Выбор: лот не старше `config.YANDEX_QUEUE_MAX_AGE_DAYS` (7 дней, иначе
    протух — выкидывается без отправки), предпочтение — модели, не
    публиковавшейся в Яндекс за последние `config.YANDEX_RECENT_MODEL_DAYS`
    (14 дней); если альтернатив нет — берём всё равно (тот же fallback, что
    у `candidate_diversity.filter_recent_models()`).
  - Ошибка Яндекс-шага НЕ блокирует TG/VK (try/except в
    `_dispatch_yandex_draft()`, тот же принцип, что у VK в
    `agent_publisher.publish_post()`) — но шлёт `⚠️ yandex draft failed: ...`
    в `YANDEX_DRAFTS_CHAT_ID`, чтобы тихий отказ не потерялся месяцами
    (черновики и так редкие).
  - `yandex_queue.json`/`yandex_published.json` — состояние, коммитится
    обратно в git из `.github/workflows/main_pipeline.yml` (та же причина,
    что у `published_log.json` — иначе не переживёт между прогонами на
    чистой VM). НЕ существуют, пока не случится первая публикация/отправка —
    шаг коммита проверяет `[ -e "$f" ]` перед `git add`, иначе `git add` на
    несуществующий путь валит весь step (`set -e`).
  - Первая строка черновика в чате — `{дата} · Черновик для Яндекса · в
    очереди ещё {N} лотов` (`yandex_publisher.send_yandex_draft(...,
    extra_header=...)`).

## Стиль работы
- Новые фичи — за флагами в `.env` (`X_ENABLED=false` по умолчанию;
  примеры: `VIDEO_ENABLED`, `VOICE_ENABLED`, `VK_ENABLED`).
- Тестовый результат (пост/ролик/статью) показывать пользователю ДО
  коммита.
- Не выдумывать несуществующие API (у Дзена нет API публикации,
  Instagram — только официальный Graph API).
