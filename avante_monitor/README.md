# Мониторинг Hyundai Avante (CN7) на HeyDealer

Каждые 6 часов проверяет аукционный зал HeyDealer и, **как только появляется новый
подходящий лот**, присылает в служебный Telegram-чат HTML-отчёт файлом + сводку
со ссылками. Про уже виденные лоты повторно не пишет.

## Активный способ запуска

**GitHub Actions** — `.github/workflows/avante_monitor.yml`, расписание `cron: "0 */6 * * *"`
(каждые 6 часов). Запуск вручную — вкладка Actions → «Avante Monitor (HeyDealer)» →
Run workflow (есть галочка `dry_run` для прогона без отправки).

Локальный запуск (разово или для отладки):

```bash
python avante_monitor/monitor_avante.py --dry-run
```

Локальный планировщик `run_scheduled.py` для этой задачи **не используется** —
он запускает `main.py` (лидоген), а не мониторинг.

## Критерии «нужного лота» (жёсткие)

| Параметр | Значение |
|---|---|
| Модель | Hyundai Avante (Elantra), кузов **CN7**, **рестайлинг 더 뉴** |
| Отсекаются | дореформенные 올 뉴, старые AD / MD / HD, а также **N / N-Line** (турбо) |
| Год | модельный **2024**, год выпуска (первая регистрация) **2023** |
| Двигатель | 1.6 **бензин**, мощность **≤ 160 л.с.** по факту |
| Пробег | **≤ 50 000 км** |
| Цвет | белый / серый / чёрный |
| Состояние | **ни одной страховой выплаты**, без ДТП, тотала, потопа и ремонта силовых элементов; косметический окрас — **не более 1** элемента |
| Цена | **не фильтруется**; лот без цены — тоже подходящий, с пометкой «цена не указана» |

Мощность берётся из `model_specs` и сверена со справочником
`~/Downloads/Список машин до 160 л.с..pdf`: **Avante 1.6 (G) = 123 л.с.**
(гибрид 1.6 = 141 л.с. — не подходит, нужен чистый бензин).

⚠️ Важная тонкость: в зале встречаются лоты «**더 뉴 아반떼** 1.6 GDi» — это рестайлинг
**старого поколения AD**, а не CN7. Поэтому проверка требует явной маркировки кузова
`CN7`, иначе в отчёт попадут машины не того поколения.

## Что создаётся за прогон

| Файл | Назначение |
|---|---|
| `report.html` | Все текущие подходящие лоты; новые помечены бейджем **NEW**. Переносимый: фото встроены как base64 (ресайз ~1200px, JPEG ~80), ссылки `target=_blank`, фото кликабельны (лайтбокс). |
| `report.xlsx` | Строка на авто, гиперссылка, автофильтр, закреплённая шапка, колонка NEW. |
| `alert_<timestamp>.html` | **Только новые лоты** этого прогона — именно он уходит в Telegram. Если новых нет, файл не создаётся. |
| `seen_lots.json` | Состояние дедупликации: `{hash: {first_seen, notified_at, car_number, url}}`. |
| `monitor.log` | Лог прогонов: время, сколько проверено/подошло/новых, ошибки. |

## Дедупликация

Ключ — **hash лота HeyDealer** (устойчив, в отличие от цены или статуса аукциона).
Новые = те, которых ещё нет в `seen_lots.json`. После успешного оповещения их id
дописываются в состояние, поэтому повторных сообщений об одном и том же лоте не будет.
Состояние коммитится обратно в репозиторий шагом workflow — иначе на чистой VM оно
теряется и бот слал бы одно и то же каждые 6 часов.

## Оповещение

Уходит в `config.ADMIN_CHAT_ID` (служебный чат), **не** в публичный канал лидогена:

1. `alert_<timestamp>.html` — документом (Bot API `sendDocument`);
2. подпись `parse_mode=HTML`: количество новых лотов и по каждому — название,
   год, пробег, мощность, цвет, цена (или «цена не указана»), статус по страховой
   и кликабельная ссылка на объявление.

Если alert-файл окажется тяжелее ~45 МБ (запас до лимита Telegram в 50 МБ) —
отправляется только текстовая сводка. Если `sendDocument` не прошёл, сводка
уходит отдельным сообщением, чтобы уведомление не потерялось.

## Секреты для GitHub Actions

Помимо уже настроенных (`BOT_TOKEN`, `ADMIN_CHAT_ID`, `TELEGRAM_CHAT_ID`,
`LOGISTICS_RUB`, `BROKER_FEE_RUB`, `MARGIN_RUB`, `BANK_COMMISSION_PCT`,
`IMPORTER_TYPE`) нужны **два новых**:

| Секрет | Что это |
|---|---|
| `HEYDEALER_ID` | логин дилерского аккаунта HeyDealer |
| `HEYDEALER_PW` | пароль от него |

Из них workflow собирает `credentials.json` на VM (сам файл в `.gitignore` и в
репозиторий не попадает). Добавить: Settings → Secrets and variables → Actions.

## Надёжность

Прогон целиком обёрнут в `try/except`: при сбое пишется лог, в служебный чат
уходит `notify_error(...)`, а процесс завершается кодом 0 — чтобы **один сбой
не ронял расписание** и следующий прогон состоялся как обычно.

Если сессия HeyDealer истекла, прогон завершится с понятной ошибкой в логе и
уведомлением. Сессия живёт недолго, поэтому в Actions логин выполняется заново
на каждом прогоне (Playwright + учётка из секретов). Данные при недоступности
площадки не выдумываются — отчёт просто не обновляется.

## Переиспользованные модули

`heydealer_scraper` (доступ к API), `model_specs` (мощность), `color_match` (цвет),
`post_builder.calculate_price_details` + `rates` (цена «под ключ» — тот же модуль,
что у лидогена), `car_report_photo_embed` (встроенные фото + лайтбокс),
`telegram_publisher` (отправка сообщения и документа), `notifier` (ошибки).
Логика парсинга, расчёта цены и шаблоны отчётов не переписывались.
